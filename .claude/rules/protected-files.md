# Protected Files

Three tiers, enforced by the harness: hard-protected, toolchain-managed, and sensitive.

## Hard-protected — NEVER modify, no exceptions
- `.git/` -- Git internals
- `.env*` (except `.env.example`/`.env.sample`) and `keys/` -- secrets, never even read (see `.claude/rules/secrets.md`)

If a task requires modifying any of these, STOP and create an implementation guide instead of making changes.

## Toolchain-managed — never hand-edit
Lockfiles are generated by their toolchain and must be committed: installs and builds (including Dockerfiles that copy them, and `npm ci`) depend on them to reproduce and verify dependencies.

| File | Toolchain | Allowed changes |
|---|---|---|
| `package-lock.json` | npm | `npm install <pkg>` adding an agreed dependency |
| `yarn.lock` | Yarn | `yarn add <pkg>` adding an agreed dependency |
| `pnpm-lock.yaml` | pnpm | `pnpm add <pkg>` adding an agreed dependency |
| `go.sum` | Go | `go mod tidy` / `go get` adding an agreed dependency |

- **Allowed:** only the changes the toolchain makes as a side effect of adding a dependency agreed under `.claude/rules/dependency-rules.md`.
- **Forbidden:**
  - Editing, truncating, deleting, moving or regenerating a lockfile by any other means.
  - Deleting a lockfile and reinstalling to "fix" something.
  - Resolving a lockfile merge conflict by hand.
  - Any command whose purpose is to change existing versions (`npm update`, `yarn upgrade`, `pnpm update`, `go get -u`). That is a dependency-version change, governed by `dependency-rules.md`.
- **Checksum or integrity mismatches** (`go.sum`, npm `integrity`) signal a tampered or changed package. Investigate them; never overwrite them.
- If adding an agreed dependency would also change the version of an existing entry, stop and report it: that is the forbidden version change.

## Sensitive — ask the user before modifying
- `.github/` -- CI/CD pipelines
- `.gitignore` -- Git ignore rules
- `Dockerfile`, `docker-compose.yml` -- container configuration

These are legitimate to edit in this workspace (projects carry their own docker-compose and .gitignore), but changes are confirmed with the user first. State what you intend to change and why before editing.

## Enforcement
This list is hard-enforced by the harness, not just by this rule text:
- `permissions.deny` / `permissions.ask` entries in `.claude/settings.json` use `Edit(path)` rules on every listed path (Edit rules cover all file-editing tools: Edit, Write, NotebookEdit; `Write(path)` rules are never matched).
- `.claude/hooks/protect-files.sh` (PreToolUse) covers shell-based writes (`rm`, `mv`, `tee`, `sed -i`, redirection) — deny for hard-protected paths, ask for sensitive ones. Read-only access (`cat`, `grep`, `git diff`) stays allowed except for secrets.

The toolchain-managed lockfiles stay in the `Edit(...)` deny rules and the hook's `HARD` pattern on purpose: together they block every hand edit (edit tools, redirection, `rm`/`mv`/`sed -i`). Toolchain commands pass because they never name the file.

When this list changes, update all three in the same edit: this file, the settings entries, and the hook's `HARD`/`SOFT` patterns.
